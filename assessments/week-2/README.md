# Week 2 Assessment — OOP, Exceptions, Collections

**Topics covered:** Days 8–14: classes, objects, constructors, this, encapsulation, inheritance, polymorphism, abstraction, interfaces, equals/hashCode, immutability, exceptions, and Collections.

1. Define a Student class with fields, a constructor, and a method that displays student information.
2. What is the difference between a class and an object?
3. Explain the purpose of a constructor and the this keyword.
4. Design a Person → Employee → Manager inheritance hierarchy with appropriate fields and methods.
5. What is encapsulation, and how can it prevent invalid object state?
6. Explain method overloading versus method overriding.
7. Design a PaymentProcessor interface and describe two classes that implement it.
8. When would you choose an abstract class instead of an interface?
9. What contract should equals() and hashCode() follow?
10. Why can incorrect equals() and hashCode() implementations cause unexpected behavior in HashSet or HashMap?
11. Describe how you would design an immutable Employee-like object.
12. Explain checked exceptions versus unchecked exceptions.
13. What is the purpose of try, catch, finally, throw, and throws?
14. Design a custom exception for an attempted bank withdrawal that exceeds the account balance.
15. Compare List, Set, Map, and Queue in terms of the kind of data each represents.
16. When would you choose ArrayList over LinkedList?
17. Build an inventory manager specification that supports adding, searching, updating, and deleting products.
18. Design a console library manager that supports listing books, borrowing, returning, and handling invalid requests.
19. Identify at least five edge cases for a library borrowing operation.
20. How would you test that a collection-backed application handles duplicate entries correctly?
