# Final Assessment — Questions Only

This assessment follows the bootcamp's final format: a 90-minute Java coding test, a 60-minute HackerRank/DSA test, a Spring Boot code review, and a 10-minute project demo. The questions below are prompts only; this file intentionally contains no solutions or answer key.

## Part A — Core Java and OOP

1. Build a small console program that validates input and handles invalid values without crashing.
2. Model a real-world domain using classes, encapsulation, inheritance or composition where appropriate.
3. Implement meaningful equals() and hashCode() behavior for a domain object and demonstrate its use in a HashSet.
4. Design a custom exception and explain where it should be thrown and handled.
5. Choose suitable collection types for a list of records, a unique set of identifiers, and a key-value lookup; justify each choice.

## Part B — Modern Java

6. Transform a list of objects using filter, map, and collect.
7. Group records by a field and calculate a summary for each group.
8. Read structured text data from a file and report malformed rows without silently corrupting valid data.
9. Describe how you would prevent unsafe concurrent updates to shared state.
10. Choose suitable Java date/time types for a start date, timestamp, and elapsed period.

## Part C — Problem Solving and DSA

11. Solve an array problem with a clearly stated approach and complexity analysis.
12. Solve a string problem using character counts or two pointers.
13. Solve a frequency-counting problem using a hash map.
14. Solve a bracket-validation problem using a stack.
15. Explain the edge cases and complexity of each solution.

## Part D — Backend and Spring Boot

16. Design a REST API for an Employee, Inventory, or Fleet Management domain.
17. Specify endpoints, HTTP methods, status codes, request DTOs, and response shapes.
18. Implement validation and consistent error responses.
19. Separate controller, service, and repository responsibilities.
20. Persist data using JPA and describe at least one entity relationship.
21. Explain how database credentials and environment-specific settings should be configured without committing secrets.
22. Describe how you would test endpoint success, validation failures, missing records, and persistence behavior.

## Part E — Project Review and Demo

23. What user problem does your final project solve, and what are its main use cases?
24. Which design decisions would you change if the project had to support substantially more users?
25. Demonstrate one successful request and one failure response.
26. Explain one bug you encountered, how you investigated it, and how you verified the fix.
27. Show the repository structure and explain how another student can run the project locally.
28. Which feature would you implement next, and why?
